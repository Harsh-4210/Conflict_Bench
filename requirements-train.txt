# ConflictBench training stack (Qwen2.5 + Unsloth + TRL GRPO). Every package is pinned to a released version.
#
# Install (Linux + NVIDIA GPU):
#   pip install -r requirements-train.txt
#
# torch / torchvision / xformers are NOT listed here so that Colab and Kaggle keep their preinstalled, matching
# CUDA build (reinstalling torch takes minutes and often breaks the image). The set below was resolved against
#   torch==2.10.0  torchvision==0.25.0  xformers==0.0.34   (CUDA 12.x)
# and training_space/Dockerfile installs exactly those. On a bare machine run first:
#   pip install torch==2.10.0 torchvision==0.25.0 xformers==0.0.34 --index-url https://download.pytorch.org/whl/cu128
#
# How these pins were chosen (resolved from the PyPI metadata of the released packages, 2026-11-01; NOT yet
# confirmed by a real GPU run - do that with configs/grpo_smoke.yaml and then refresh as described below):
#   unsloth 2026.10.6 / unsloth_zoo 2026.10.6 accept   trl >=0.18.2,<=1.15.0   transformers >=4.52.4,<=5.17.0
#                                                      peft >=0.18.0           datasets >=3.4.1,<5 (not 4.4.*)
#   trl 1.13.0 needs transformers >=4.56.2, datasets >=4.7.0, accelerate >=1.4.0
#   transformers 4.57.6 needs huggingface-hub <1.0  ->  huggingface_hub 0.36.2
#   We stay on the transformers 4.x line (4.57.6, the last 4.x release; 4.57.4 and 4.57.5 are excluded by Unsloth).
#
# How to refresh the pins after a working run:
#   1. Run a smoke test:   python -m training.train_grpo --config configs/grpo_smoke.yaml
#   2. It writes results/grpo_smoke/pip_freeze.txt (exact versions that just worked).
#      Or run `pip freeze | grep -iE "^(unsloth|unsloth_zoo|trl|transformers|peft|accelerate|datasets|bitsandbytes|huggingface-hub|sentencepiece|protobuf|pyyaml|matplotlib|torch|torchvision|xformers|triton)=="`
#   3. Copy those versions here (and the torch/xformers ones into training_space/Dockerfile), then re-run the smoke
#      test and commit this file together with the new results/<run>/pip_freeze.txt.
