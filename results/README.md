# results/

Everything here is produced by scripts in `scripts/`. Nothing in this folder is typed by hand, and
`leaderboard.md` is regenerated from the `summary.json` files.

```
results/
  leaderboard.md                  generated by scripts/make_leaderboard.py
  data/gen_<split>_n<N>_seed<S>_<sha8>.jsonl   sets built by --generate (name carries the hash);
                                  gen_n600_seed1234_20eb83f9.jsonl is the old (pre-Phase 3) task
  ../data/test_v1.jsonl           THE fixed test set (Phase 3 task, held-out split); its hash is
                                  in ../data/test_v1.sha256. Report model results on this file.
  <run_name>/summary.json         run metadata + mean composite, 95% bootstrap CI, per-difficulty,
                                  per-rubric, parse-failure rate, n, skipped-too-long count
  <run_name>/completions.jsonl    every completion with its full score (scenario_id, difficulty,
                                  sample, completion, score{...})
  baselines.json                  old task + old verifier (the audit numbers)
  baselines_v2.json               old task + new verifier
  baselines_test_v1.json          new task, test split (scripts/baselines.py)
```

Rows are only comparable when they share one data set. `summary.json` stores the SHA-256 of the data
file and the git commit, and `leaderboard.md` puts each data hash under its own heading. If the
generator changes, `--generate` writes a new file with a new hash instead of overwriting the old one.

Setup for the CPU rows: Python 3.10+ and `pip install -r requirements-dev.txt` (needs no torch).

## Rebuild the leaderboard

```
python scripts/make_leaderboard.py
```

## Rule-based and cheat strategies (no model, CPU, about 10 s each)

Score every strategy on the fixed test set:

```
for s in $(python -c "from scripts.baselines import STRATEGIES; print(' '.join(STRATEGIES))"); do
  python scripts/evaluate.py --strategy $s --data data/test_v1.jsonl --run-name "${s}__test_v1"
done
python scripts/make_leaderboard.py
```

`--generate N --seed S [--split test]` builds a fresh set instead and writes
`results/data/gen_<split>_n<N>_seed<S>_<sha8>.jsonl`, reusing it if the generator still produces
the same bytes.
`--limit N` scores only the first N scenarios (for smoke tests).

`ground_truth` and `gt_one_conflict_flipped` are sanity checks for the verifier, not baselines
to beat: 1.0 and a partly wrong answer. `oracle_lookup`, `latest_wins` and
`keyword_restrictive_v2` are the "no learning needed" rule solvers (they even read hidden
structured fields); a trained model has to be judged against them. `resolver` is the exact solver.

## Local model (GPU) and API rows (not run yet)

These rows need a GPU or an API key. They are **not measured yet**. The commands below are what
to run; each writes its own `results/<run_name>/` folder and a new leaderboard row.

### Qwen2.5-3B-Instruct base model (P4-2 item 3)

Free Colab or Kaggle T4 is enough for 600 short prompts. Greedy decoding, the chat template,
no truncation (prompts too long for the context window are skipped and counted).

```
# new notebook, GPU runtime (T4)
!git clone https://github.com/Harsh-4210/Conflict_Bench.git
%cd Conflict_Bench
!git checkout <a commit that contains data/test_v1.jsonl>
!pip -q install transformers accelerate peft torch
!python scripts/evaluate.py \
    --model Qwen/Qwen2.5-3B-Instruct \
    --data data/test_v1.jsonl \
    --run-name qwen2.5-3b-instruct_base \
    --max-new-tokens 1024
```

Then download `results/qwen2.5-3b-instruct_base/` (small), copy it into your checkout and run
`python scripts/make_leaderboard.py`. The same run with sampling for pass@k:
add `--samples 4 --temperature 0.7` and a different `--run-name`.

### Any OpenAI-compatible API model (frontier or big open model)

The key is read from the environment only; it is never written to a file, a log or `summary.json`
(only the base URL without credentials is stored).

```
export CONFLICTBENCH_API_KEY=...        # Windows PowerShell: $env:CONFLICTBENCH_API_KEY = "..."
python scripts/evaluate.py \
    --api https://api.groq.com/openai/v1 --api-model <model name> \
    --data data/test_v1.jsonl \
    --run-name <short name>
```

Temperature is 0 unless you pass `--temperature`. Requests retry with exponential backoff on
429/5xx and network errors. Watch the free-tier daily token cap before running all 600.

## How a row is scored

The prompt is `prompts.build_messages(scenario)`, the same text training uses. Each completion
is scored by `verifier.score`. A scenario's value is the mean over its samples; the 95% interval
is a percentile bootstrap over scenarios (1000 resamples, seed 0), so it is repeatable.
With `--samples k` the summary also has `pass_at_k` (a scenario counts if any sample has
`correct_final_state` of at least 0.999) and `best_of_k_composite`.
